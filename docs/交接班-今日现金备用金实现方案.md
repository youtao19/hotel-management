# 今日现金备用金实现方案

## 1. 已确认的业务规则

- 仅管理现金备用金；微信、微邮付、其他继续沿用现有口径。
- 今日现金备用金的唯一来源是按营业日期保存的设置记录。
- 不再使用固定 `320`，也不从昨日交接记录推导现金备用金。
- 某日尚未设置现金备用金时，该日不能完成交接班。
- `0` 是允许保存的备用金金额；“未设置”和“设置为 0”必须能区分。
- 交接完成后，当日现金备用金不可再修改，避免已保存的交接快照与后续计算不一致。

## 2. 数据模型

新增表 `handover_daily_settings`，每天最多一条记录，不按支付方式拆行：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `business_date` | `DATE`，唯一 | 营业日期，直接使用 `YYYY-MM-DD` |
| `cash_reserve` | `NUMERIC(10,2)`，非空 | 当日现金备用金，允许为 `0`，不得小于 `0` |
| `set_by` | `VARCHAR(50)`，非空 | 最后设置人 |
| `created_at` | `TIMESTAMPTZ` | 首次设置时间，由数据库默认生成 |
| `updated_at` | `TIMESTAMPTZ` | 最后修改时间，由数据库默认生成并在更新时写入 |

约束：`UNIQUE (business_date)`。

这张表保存的是交接前的日设置，不替代现有 `handover` 表。`handover` 仍只保存用户点击“完成交接”后按四种支付方式生成的最终快照。

## 3. 后端接口与数据流

### 3.1 设置今日现金备用金

新增接口：`PUT /api/handover/daily-cash-reserve`

请求：

```json
{
  "date": "2026-07-30",
  "cashReserve": 320
}
```

后端规则：

1. 校验 `date` 是 `YYYY-MM-DD`，`cashReserve` 是大于等于 0、至多两位小数的金额。
2. 查询该日期是否已完成交接（`handover` 四种支付方式齐全）。若已完成，返回冲突错误，拒绝修改。
3. 使用当前登录账号作为 `set_by`，按 `business_date` UPSERT 设置记录。
4. 返回已保存的日期、现金备用金和设置人；不返回或接受前端计算出的交接款。

### 3.2 加载交接页面

现有 `GET /api/handover/overview?date=YYYY-MM-DD` 增加：

```json
{
  "cashReserveSetting": {
    "configured": true,
    "amount": 320,
    "setBy": "youtao",
    "updatedAt": "数据库返回的时间"
  }
}
```

- 有设置记录：现金行的 `paymentData.reserve.现金` 必须等于该记录的 `amount`。
- 没有设置记录：`configured` 返回 `false`，现金备用金在表格中显示“未设置”，并在 `completeBlockReasons` 中返回“请先设置今日现金备用金”。
- 不能以 `0` 判断是否设置，必须以记录是否存在（或 `configured`）判断。

### 3.3 完成交接

现有 `POST /api/handover/complete` 的请求体不增加备用金字段。后端必须在同一业务流程中重新读取 `handover_daily_settings`：

```text
当天 bills 汇总
  + handover_daily_settings.cash_reserve
  + 前端提交的留存款
  = 后端重算的现金交接款
```

若找不到当日设置记录，接口返回业务校验错误，不写入任何 `handover` 记录。这样即使有人绕过前端直接调用完成接口，也不能使用旧的固定 `320` 或伪造备用金。

## 4. 页面交互

在“昨日记录缺失”状态徽标左侧增加按钮：

- 未设置：`设置今日现金备用金`
- 已设置但未完成交接：`修改今日现金备用金`
- 已完成交接：显示金额但按钮禁用，提示“当日交接已完成，备用金不可修改”

点击按钮打开金额输入弹窗：

- 显示当前所选营业日期。
- 输入项为“现金备用金（元）”，保留两位小数，允许输入 `0`，禁止负数。
- 保存成功后重新加载 `overview`，由后端返回的新金额刷新表格及应交款合计。
- 未设置时，现金备用金单元格显示“未设置”，完成交接按钮禁用，并显示后端返回的阻断原因。

## 6. 验收标准

1. 新日期未设置备用金时，概览明确显示“未设置”，且无法完成交接。
2. 设置 `500.00` 后，现金备用金与现金交接款均由后端返回并刷新。
3. 设置 `0.00` 后，系统识别为“已设置”，允许继续交接。
4. 直接调用完成接口但未设置备用金时，后端返回校验错误且 `handover` 不产生新记录。
5. 已完成交接后，再调用设置接口返回冲突错误，保存的交接快照不发生改变。
