# 2026 年 1 月交接班逻辑分析

## 范围

只分析 `2026.1月流水账.xlsx` 中每日 Sheet（`1.1` 至 `1.31`）末尾的“交接班”区，不分析订单明细、比价或营业额汇总。

## 结论

这份表的交接班是按 **支付方式** 做现金流核对，而不是直接将当天营业额交出。每个支付方式独立计算，最后得到该方式本班次应交金额。

早期 Sheet 的标准列为：

`支付方式` → `备用金` → `客房收入` → `休息房收入` → `其他收入` → `合计` → `客房退押` → `休息退押` → `其他扣减` → `留存款` → `交接款`

支付方式固定为：现金、微信、微邮付、其它方式。

## 核心公式

对每一个支付方式，Excel 中的实际公式是：

```text
合计 = 备用金 + 客房收入 + 休息房收入 + 其他收入
交接款 = 合计 - 客房退押 - 休息退押 - 其他扣减 - 留存款
```

例如 `1.2` Sheet 的现金行：备用金 320、休息房收入 80、其他收入 800，所以合计为 1,200；扣除“其他”800 和留存款 320 后，交接款为 80。微信行也按照相同公式计算。

## 字段的业务含义

| 字段 | 交接含义 |
| --- | --- |
| 备用金 | 本班开始时已在该支付方式下的余额。现金通常用于保留找零；微信、微邮付的数值更像待交或待核的渠道余额。|
| 客房收入、休息房收入、其他收入 | 本班新增收款，必须归属到实际支付方式。预订定金、续住补差、超时费、税点等只要已收，也会进入对应收入列。|
| 合计 | 本班可被核对的总资金池，不是“当天收入”。|
| 客房退押、休息退押 | 实际已退给客人的金额，必须从应交资金中扣除。|
| 其他扣减 | 非标准退押但已从该支付方式流出的金额，例如换支付方式、老板/管理人员拿走、渠道间调账等。|
| 留存款 | 不在本次交接中上交、但需继续留在该支付方式中的金额。现金通常保留固定找零金额；线上渠道是否留存依现场规则填写。|
| 交接款 | 本班实际应移交或应核对的净额。它由公式自动计算，不应手工覆盖。|

## 跨日期观察

1. **现金备用金通常为 320，但不是公式继承。**
   多数日期是 320；`1.30` 的现金备用金为 300，而 `1.31` 又为 320。备用金单元格没有跨 Sheet 引用，说明它是交班时人工确认的期初余额，不应直接假定等于前一天交接款。
2. **收入、退款、留存和交接款均按支付方式隔离。**
   例如微信收入不能与微邮付退款直接相抵；如发生“微邮付收、微信退”或“现金换微信”，原表会在对应两行及备忘录中分别体现。
3. **备忘录是交接的一部分。**
   它记录待退押、待评价后退款、续住/换房、未付预订、渠道调账等尚未结清事项。金额表只能说明资金状态，备忘录补充后续接班人必须处理的动作。
4. **附加运营指标不参与金额公式。**
   “好评、开房、收银员、大美卡、休息房、备注、携程卡”等位于交接表下方，用于班次运营交接，不参与交接款计算。

## 月底表头变更与注意事项

`1.29` 起，“留存款”和“交接款”整体右移一列：交接款从 K 列移到 L 列，计算公式仍然是“合计减退款、其他扣减和留存款”。`1.30` 与 `1.31` 的 K 列表头写成“备用金”，但 L 列公式明确扣除了 K 列；结合上下文，该 K 列实际承担的是 **留存款** 角色，应视为表头录入错误，不能按第二个备用金处理。

## 对系统交接班页面的落地建议

1. 后端按支付方式聚合本班收款、退款和其它扣减，前端只展示计算结果。
2. 后端以统一公式重新计算 `交接款`，不信任前端传入的合计或交接款。
3. 将 `备用金`、`留存款` 和 `其它扣减` 分开存储，避免把渠道调账误判为退款。
4. 交班时同时保存结构化金额明细与备忘录；备忘录中的待处理事项应能被下一班查看。
5. 对月底这种列变更不能照搬 Excel 的位置，应以语义字段建模：`reserve`、`income`、`refund`、`otherDeduction`、`retainedAmount`、`handoverAmount`。
